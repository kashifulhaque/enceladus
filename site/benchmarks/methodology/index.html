Benchmarks

Methodology

How the benchmark scripts time Enceladus, MLX, and PyTorch, which statistic each table reports, the machine that produced the results, and how to run the benchmarks yourself.

How Enceladus kernels are timed

Every Enceladus throughput number comes from enceladus.testing.do_bench, which reads GPU timestamps instead of the wall clock. For each call, do_bench does the following:

  1. Raises the stream's flush threshold so that each repetition runs in its own command buffer.
  2. Runs the function until it has spent 50 ms of GPU time. The GPU clocks down when it's idle, so cold measurements run slow.
  3. Runs the function rep times, and records the GPU start and end time of each command buffer.

Because the time comes from the command buffer, it excludes host-side launch cost and synchronization. The function must launch on enceladus.Tensor arguments; a launch that synchronizes internally can't be timed this way. For more information, see Performance.

How MLX and PyTorch are timed

MLX and PyTorch don't expose per-command-buffer GPU timestamps to these scripts, so their times use the wall clock around a synchronized call: mx.eval(...) for MLX, and the operation followed by torch.mps.synchronize() for PyTorch. Each script runs a few warmup calls first.

The wall clock includes launch and synchronization overhead, which the softmax and attention scripts estimate at about 0.1 ms. That overhead is small for long kernels, for example under 1% for a 4096³ matmul, but it's a large fraction of a kernel that runs for well under a millisecond. When a comparison involves a short kernel, read the MLX and PyTorch numbers as lower bounds on their throughput.

Minimum and median

Most tables report the minimum time over the repetitions, converted to throughput. The minimum is the least noisy estimate of what the kernel can do when nothing else interferes. Where the scripts also report the median, the tables show it in parentheses or in its own column. A large gap between the two means the kernel's time varies from run to run; for example, the float32 mpp matmul at 4096³ has a minimum of 5.35 TFLOPS and a median of 3.36.

Interleaved rounds

GPU clocks, temperature, and other GPU users change during a run. To spread those changes evenly across the kernels under comparison, two scripts interleave their measurements:

  • bench_matmul times every variant for one shape and dtype in turn, for 3 rounds of 10 runs, and reports the minimum and median over all 30 samples.
  • bench_attention alternates the Enceladus kernel and MLX in one process for 3 rounds of 10 runs. It reports the best round's minimum and the median of the round medians.

Throughput units

The scripts convert times to throughput as follows:

  • Memory-bound kernels report GB/s, counting the minimum traffic: each input read once and each output written once. A kernel that rereads data from the cache can report less than its real traffic.
  • Matmul reports TFLOPS as 2 × M × N × K floating-point operations per time.
  • Attention reports TFLOPS as 4 × batch × heads × sequence length² × head dimension operations per time, halved for a causal mask.
  • Dispatch overhead reports microseconds per launch, measured on the host with the wall clock.

Reproduce the results

To run the benchmarks on your own Mac, follow these steps:

  1. Clone the repository and install the development environment, which includes MLX and PyTorch:
    shell
    uv sync
  2. Close other GPU-heavy apps, and connect the computer to power.
  3. Run every benchmark and write a report:
    shell
    uv run python benchmarks/run_all.py

    The script writes a Markdown report named DATE-ARCHITECTURE.md to benchmarks/results/, with one section per benchmark.

To run one benchmark, run its script directly, for example:

shell
uv run python benchmarks/bench_matmul.py --quick

The --quick flag limits bench_matmul to the 4096³ shape and bench_attention to sequence length 2048. run_all.py doesn't include bench_scan_atomics.py, so run that script on its own. A script skips its MLX or PyTorch rows when that framework isn't installed, except bench_attention, which requires MLX.
