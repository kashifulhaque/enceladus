Benchmarks

Elementwise

Vector add bandwidth on large arrays against MLX, plus the time Enceladus takes to compile a kernel from Python to MSL.

What it measures

bench_elementwise runs the vector add from examples/01_vector_add.py, out = x + y, on 226 elements. That's 256 MB per array in float32 and 128 MB in float16, far larger than the GPU's caches. The script measures the following:

  • Enceladus with BLOCK=1024 and BLOCK=4096, in float32 and float16, as the minimum of 20 GPU-timed runs.
  • MLX's x + y on the same shape and dtype, as the minimum of 20 wall-clock runs after 10 warmup runs. The script measures MLX again for each row.
  • The compile time of the vector add, from the Python frontend to MSL, as the median of 50 compilations. This excludes Metal's own compilation of the MSL.

GB/s counts three arrays of traffic: two reads and one write.

The vector add compiles from the frontend to MSL in 0.37 ms.

Reading the results

  • Both dtypes reach the same bandwidth. float16 moves half the bytes in about half the time, so the kernel is bound by memory bandwidth, not by instruction count.
  • Block size matters little. BLOCK=1024 is slightly faster than BLOCK=4096 in both dtypes: 224.1 against 216.3 GB/s in float32, and 221.4 against 220.6 GB/s in float16.
  • Enceladus leads MLX by 1-9%. MLX's own number varies from 205.8 to 214.6 GB/s between rows of the same run, so treat differences of a few percent as noise. MLX's time also includes wall-clock overhead.
  • Compilation is cheap. At 0.37 ms, the Python-to-MSL step costs less than one launch of this kernel on 256 MB arrays.

For guidance on block sizes and SIMD groups for memory-bound kernels, see Performance.
