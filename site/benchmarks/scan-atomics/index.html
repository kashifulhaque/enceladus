Benchmarks

Scans and atomics

Row cumulative-sum bandwidth against MLX, and the throughput of a histogram built with global atomics.

What it measures

bench_scan_atomics runs two example kernels:

  • Row cumsum from examples/10_cumsum.py, on a 4096 × 4096 float32 matrix, one row per program, with 4, 8, and 16 SIMD groups. It compares against mx.cumsum(x, axis=1). GB/s counts one read and one write of the matrix.
  • Histogram from examples/09_histogram.py, on 224 normally distributed float32 values, with 64 and 4,096 equal bins over [-4, 4). Each value adds one count to a shared histogram in device memory with tl.atomic_add. GB/s counts one read of the input.

Enceladus times are the minimum of 20 GPU-timed runs. The MLX time is the minimum of 20 wall-clock runs after 10 warmup runs, so it includes about 0.1 ms of launch and synchronization overhead.

Reading the results

  • The scan runs at copy bandwidth. The row cumsum reaches 241.0-242.2 GB/s, close to the row softmax on the same matrix, and the SIMD-group count changes it by under 1%.
  • The lead over MLX is mostly overhead. MLX's 189.5 GB/s corresponds to about 0.71 ms, against 0.55-0.56 ms for Enceladus. That 0.15 ms difference is only a little more than the wall-clock overhead of about 0.1 ms, so the data doesn't show that the Enceladus kernel is much faster.
  • Atomic contention limits the histogram. Every count goes to a counter in device memory, and there are no threadgroup-memory atomics to privatize the counters per threadgroup. With 64 bins, normally distributed values pile onto a few central counters, and the kernel reaches 31.1 GB/s. With 4,096 bins, the same values spread over more counters, and throughput doubles to 62.5 GB/s.

For the atomic and scan builtins, see the language reference.
