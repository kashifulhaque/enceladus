Benchmarks

Dispatch overhead

The host cost of launching a kernel through each Enceladus path, next to the native dispatch floor and PyTorch's own launch paths.

What it measures

bench_dispatch launches a 1,024-element float32 vector add, which does almost no GPU work, so the time per launch is launch overhead. It measures two patterns with the host's wall clock:

  • Sustained: 10,000 back-to-back launches followed by one synchronization, repeated 5 times. The result is the time per launch. The stream commits a command buffer every 64 dispatches.
  • Sync round trip: 300 launches that each wait for the GPU before the next one starts.

The script compares the following launch paths:

  • A raw enceladus.metal_kernel with handwritten MSL.
  • The native Stream.dispatch call with prebuilt arguments, which is the floor for any Python launch.
  • An @enceladus.jit kernel, which also binds arguments, computes the specialization key, and packs arguments.
  • The same @enceladus.jit kernel on PyTorch MPS tensors and on MLX arrays.
  • PyTorch floors: a torch.mps.compile_shader kernel called directly, and torch.add(out=).

Before measuring, the script warms up the GPU clocks with 20,000 launches.

Reading the results

  • The GPU sets the floor. The native dispatch call and the raw metal_kernel launch both cost about 1 µs, which is the GPU's cost for a dependent dispatch. Python adds almost nothing on the raw path.
  • @enceladus.jit adds about 2.4 µs. Binding, the specialization key, and argument packing bring a launch to 3.41 µs, which is still well under a synchronized round trip.
  • The PyTorch path is host-bound. A launch on MPS tensors costs 5.10 µs, against 2.23 µs for the same MSL through compile_shader called directly, and 1.98 µs for a built-in torch.add.
  • Synchronization dominates small kernels. A round trip costs 70-100 µs, 20 to 30 times a sustained @enceladus.jit launch. MLX launches are synchronous, so every launch on MLX arrays pays this cost.

To keep launches asynchronous, allocate with enceladus.empty, zeros, or randn, and synchronize only when you need the result. For more information, see Performance and Framework interop.
