Benchmarks

Dispatch overhead

The host cost of launching a kernel through each Enceladus path, next to the native dispatch floor and the launch paths of PyTorch and MLX.

What it measures

bench_dispatch launches a 1,024-element float32 vector add, which does almost no GPU work, so the time per launch is launch overhead. It measures three patterns with the host's wall clock:

  • Sustained: 10,000 back-to-back launches followed by one synchronization, repeated 5 times. The result is the time per launch. The stream commits a command buffer every 64 dispatches.
  • Sync round trip: 300 launches that each wait for the GPU before the next one starts.
  • Lazy chain: on MLX arrays, a chain of 1,000 dependent launches followed by one mx.eval, repeated 10 times. The result is the time per launch.

The script compares the following launch paths:

  • A raw enceladus.metal_kernel with handwritten MSL.
  • The native Stream.dispatch call with prebuilt arguments, which is the floor for any Python launch.
  • An @enceladus.jit kernel, which also binds arguments, computes the specialization key, and packs arguments.
  • The same @enceladus.jit kernel on PyTorch MPS tensors and on MLX arrays.
  • The same @enceladus.jit kernel on MLX arrays with enceladus.lazy_mlx(True), where each launch writes a fresh output from enceladus.new_empty and joins MLX's lazy graph instead of waiting.
  • PyTorch floors: a torch.mps.compile_shader kernel called directly, and torch.add(out=).
  • MLX floor: a chain of 1,000 x + y additions in MLX itself.

Before measuring, the script warms up the GPU clocks with 20,000 launches.

Reading the results

  • The GPU sets the floor. The native dispatch call and the raw metal_kernel launch both cost about 1 µs, which is the GPU's cost for a dependent dispatch. Python adds little on the raw path.
  • @enceladus.jit adds about 2.4 µs. Binding, the specialization key, and argument packing bring a launch to 3.39 µs, which is still well under a synchronized round trip.
  • The PyTorch path is host-bound. A launch on MPS tensors costs 4.59 µs, against 2.31 µs for the same MSL through compile_shader called directly, and 2.08 µs for a built-in torch.add.
  • Synchronization dominates small kernels. A round trip costs 83-126 µs by minimum time, about 25 to 37 times a sustained @enceladus.jit launch. By default, launches on MLX arrays are synchronous, so each one pays this cost.
  • Lazy MLX launches avoid the round trip. With enceladus.lazy_mlx(True), a chain of launches costs 13.38 µs per launch, about a tenth of a synchronous launch on MLX arrays. That's still about 8 times MLX's own x + y, at 1.69 µs.

To keep launches asynchronous, allocate with enceladus.empty, zeros, or randn, and synchronize only when you need the result. On MLX arrays, call enceladus.lazy_mlx(True) and write each result to a fresh output from enceladus.new_empty. For more information, see Performance and Framework interop.
