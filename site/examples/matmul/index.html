Examples

Matrix multiplication

c = a @ b with a float32 accumulator, written two ways: with pointer tiles and masks, and with tensor descriptors. The descriptor version also has an autotuned wrapper.

What it computes

The file defines three wrappers that return a @ b in the input dtype:

  • matmul uses pointer tiles with masks. The operands can have any strides.
  • matmul_desc uses tensor descriptors, so tl.dot loads its fragments straight from device memory. This is the fast path. a, b, and c must be row-major.
  • matmul_tuned runs the descriptor kernel with the fastest configuration for the shape and dtype.

All three accept NumPy arrays, enceladus.Tensor objects, PyTorch tensors on the mps device, and MLX arrays, and return an array of the same kind.

Pointer tiles

The following code shows the pointer-tile kernel and its wrapper:

  • The grid is two-dimensional. Axis 0 walks the BN-wide column blocks of c, and axis 1 walks the BM-tall row blocks. The grid is a function of meta, so it reads the block sizes from the launch.
  • a_ptrs and b_ptrs are 2D tiles of pointers, built from row and column offsets with [:, None] and [None, :] broadcasting and the strides that enceladus.element_strides returns.
  • Each iteration of the K loop masks both the M or N edge and the K tail, loads zeros outside the matrices, and accumulates with acc = tl.dot(a, b, acc). It then advances both pointer tiles by BK along K.
  • The store casts the accumulator to c_ptr.dtype.element_ty and masks the edges of c.

Pointer-tile operands go through threadgroup memory before tl.dot uses them. That works for any tile, but runs slower than the descriptor version.

Tensor descriptors

The following code shows the descriptor kernel and its wrapper:

  • tl.make_tensor_descriptor describes each matrix by its base pointer, shape, strides, and block shape. The innermost stride must be 1, so the wrapper passes only the row strides: k, n, and n.
  • Descriptors check their own bounds. a.load fills out-of-bounds elements with zeros, and c.store skips them, so the kernel has no masks.
  • The defaults are 64 by 64 output blocks, a K step of 32, and 4 SIMD groups. With dot_backend="mpp", the K loop runs as one Metal 4 matmul2d operation.

For more information about the two ways to address memory, see Memory and synchronization. For the tl.dot backends, see Performance.

Autotuning

The following code wraps the descriptor kernel in enceladus.autotune:

  • The candidate list is matmul_configs("float16"), which is a superset of the float32 list.
  • _configs_for_dtype, passed as early_config_prune, keeps only the configurations that matmul_configs lists for the dtype of a. This keeps the float32 shapes that spill registers out of float32 tuning.
  • The tuning key is M, N, and K. The autotuner also keys on the argument dtypes, so it tunes each dtype separately.
  • The grid is a function of meta, because the block sizes come from the chosen configuration.

The demo doesn't call matmul_tuned. For more information about autotuning, see Performance.

Run the example

From the root of a clone of the repository, run the following command:

shell
uv run python examples/04_matmul.py

The demo multiplies a 100 by 70 matrix by a 70 by 90 matrix, in float32, with matmul and with matmul_desc. None of the dimensions is a multiple of the block sizes, so both kernels exercise their edge handling. It compares each result with NumPy, and the output is similar to the following:

max abs error, pointer tiles: 0.0
max abs error, descriptors: 0.0
