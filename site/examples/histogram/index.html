Histogram

A histogram of floating-point data, built with tl.atomic_add. Every program adds its counts to one shared histogram in device memory.

What it computes

histogram(x, num_bins, lo, hi) counts the values of a NumPy array in num_bins equal bins over [lo, hi), and returns the counts as int32. It skips values outside that range.

How it works

  • The grid has cdiv(n, block) programs, and each one bins BLOCK values.
  • The wrapper passes inv_width = num_bins / (hi - lo), so the kernel computes each bin with a multiply instead of a divide: tl.floor((x - lo) * inv_width), converted to int32.
  • The mask ok combines the bounds check, offs < n, with the bin range, 0 <= b < NUM_BINS. Out-of-range values don't touch the histogram.
  • tl.atomic_add(hist_ptr + b, 1, mask=ok) adds one count per value. Many programs update the same bins at once, and the atomic add keeps the counts exact.
  • The wrapper starts from np.zeros, because the kernel only adds to the histogram.

Enceladus atomics use relaxed memory ordering, and float16 and bfloat16 atomic_add isn't supported. For details, see Atomics in the language reference.

Run the example

From the root of a clone of the repository, run the following command:

shell
uv run python examples/09_histogram.py

The demo bins 1,000,000 normally distributed float32 values into 64 bins over [-4, 4). The NumPy reference bins in float32 with the same formula, so the counts must match exactly. The output is similar to the following:

counts match: True
