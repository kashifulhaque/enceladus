Matmul with bias and GELU

A descriptor matmul with a fused epilogue: gelu(a @ b + bias). The bias add, the GELU, and the cast run on the accumulator registers before the store.

What it computes

matmul_bias_gelu(a, b, bias) returns gelu(a @ b + bias) in the input dtype, where bias has one value per output column. a, b, and the output must be row-major. For a NumPy a, the wrapper allocates a NumPy output; for any other input, it allocates an enceladus.Tensor, unless you pass c.

How it works

The K loop is the same as in the descriptor kernel of the matrix multiplication example: three tensor descriptors, a 2D grid over the output blocks, and acc = tl.dot(a_tile, b_tile, acc) with a float32 accumulator. After the loop, the kernel runs the epilogue on the accumulator:

  1. Load the BN bias values for the block's columns with a pointer tile, masking columns past N.
  2. Add the bias to every row with bias[None, :] broadcasting.
  3. Apply the exact GELU with tl.erf.
  4. Cast to the output dtype and store through the output descriptor, which skips out-of-bounds elements.

These steps work on the accumulator's registers in place, so the fused kernel costs about the same as a plain matmul. With dot_backend="mpp", the epilogue runs on the elements of the Metal 4 matmul2d cooperative tensor. For more information, see Performance.

Run the example

From the root of a clone of the repository, run the following command:

shell
uv run python examples/07_matmul_fused.py

The demo multiplies a 200 by 96 matrix by a 96 by 130 matrix in float32, adds a 130-element bias, and compares the result with a NumPy reference computed in float64. The output is similar to the following:
